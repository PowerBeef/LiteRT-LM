## Terms (for glossary.md)

| term | meaning | prefer / avoid |
| --- | --- | --- |
| Preface | The fixed start of a conversation (`JsonPreface`: messages, tools, extra context), rendered into the first prefill; not part of `GetHistory()` | prefer "preface"; avoid "history" for it |
| History | Messages sent with `SendMessage` and the completed replies (`history_`) | |
| Channel | A named span of model output between start and end strings (`thought` for Gemma 4), streamed and stored apart from the answer | prefer "channel"; "thinking channel" for `thought` |
| Reasoning channel | A channel named `thought` or flagged `is_reasoning_channel`; its text is copied to `reasoning_content` | |
| Channel filter | Removing channel text from the KV cache by rewinding to a checkpoint and prefilling the reply without it (`filter_channel_content_from_kv_cache`) | avoid "deleting" (nothing is erased; positions are overwritten) |
| Refill | The prefill of the reply re-rendered without reasoning after a rewind | |
| Prefill text (turn difference) | `render(history + new)` minus `render(history)`: what a later turn sends to the session | avoid "the prompt" for it |
| Single-turn template | A template that contains `is_appending_to_prefill` and can render one message at a time; Gemma 4 E2B/E4B files don't have one | |
| Model data processor | The model-specific converter between messages and session inputs (`Gemma4DataProcessor`) | |
| Constraint provider | Builds per-message constraints: llguidance or external (`ConstraintProviderConfig`) | |
| FST provider / Gemma model constraint provider | Google's closed prebuilt library that builds tool-call constraints for Gemma processors | prefer "the closed Gemma FST provider"; it is not a `ConstraintProvider` |
| llguidance | Open Rust library for regex, JSON-schema and Lark constraints | |
| Response format | Swift `ResponseFormat` (JSON schema or regex), sent as an llguidance constraint | |
| Code fence | The tool-call delimiters (`<\|tool_call>`, `<tool_call\|>` for Gemma 4) | |

## Notes for other pages

- **engine-and-sessions.md**: `SessionAdvanced::RewindToCheckpoint` restores step, state and task dependencies only; `SaveContext`/`RestoreContext` keep a `ProcessedContext` (LM-CNV-055, LM-CNV-087). `RunPrefillAsync` tokenizes on the caller's thread before queuing (LM-CNV-040). BOS is added on a fresh session's first prefill when session templating is off (LM-CNV-015). `CancelProcess` is documented as poisoning the session (LM-CNV-082).
- **executors.md**: `SetCurrentStep` only moves `current_step` and unprimes MTP; whether the stop token that ended a reply is written to the KV cache at the next prefill (pending input token) decides what the cache holds at turn boundaries (open question here). The MTP drafter receives the constraint at the pin; Agello turns MTP off for JSON helpers because of failures on the shipped binary (LM-CNV-079).
- **components.md**: llguidance EOS defaults to the first single-token stop sequence (token 1 for Gemma 4 files, LM-CNV-066); `ThinkingBudgetConstraint` wraps the user constraint whenever the budget is non-zero (LM-CNV-049); the llguidance tokenizer is built from the whole vocabulary on each provider creation, i.e. per conversation with `enableResponseFormat` (LM-CNV-067).
- **swift-api.md**: `filterChannelContentFromKvCache` is passed only when non-nil (LM-CNV-057); `responseFormat` is skipped for user messages when tools and automatic tool calling are on (LM-CNV-064); the tool loop limit is 25 and the per-message thinking config is passed only on the first call (LM-CNV-063).
- **c-api.md**: the system message and `set_messages` become preface messages, not history (LM-CNV-022); only regex and JSON-schema constraints, only the llguidance provider (LM-CNV-068); no `task_group_id`, no `has_pending_message`, no `prefill_preface_on_init`, no `return_error_on_*` setters.
- **models/tokenizer-and-chat-format.md**: the file template's turn markers, `strip_thinking`, tool-call and tool-response formats, and its differences from the HF template (LM-CNV-025, LM-CNV-026, LM-CNV-027); the `-gpu` files' variant (LM-CNV-028); start token 2 and stop tokens 1, 50, 106 (LM-CNV-017).
- **models/gemma4-e4b.md / gemma4-e2b.md (C2)**: the runtime's default image budget is 2520 / 9 = 280 tokens; budgets are validated against the engine's max vision tokens per image (LM-CNV-034, LM-CNV-035).
- **troubleshooting.md**: "new rendered template string does not start with the previous" (template prefix mismatch); "Tool-call constraints need the FST constraint provider" (expected in our build, skipped); "Max number of tokens reached, context window out of bounds" (only with `return_error_on_max_tokens_reached`); "Provided less/more images than expected"; "has_pending_message is only valid for ... single turn" (Gemma 4); a JSON constraint that keeps applying to later messages (LM-CNV-071).
- **patches.md**: `d1488ce7` (keep response formats without the FST provider) and `43f0f5c3` (the define in `--config=agello`) are the conversation-layer changes of ours; upstream candidate: the sticky `constraint_` (LM-CNV-071).
- **versions.md**: v0.18.0 → agello-next conversation changes: eager channel refill (`97e6dc7d`), `CountTokens` (`8eca57a5`), `WaitUntilDone`, status-code C API.
