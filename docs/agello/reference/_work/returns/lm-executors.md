## Contradictions

- **C9 (not assigned; data for B1 / memory.md).** 918 MB and 940 MB are both right for different allocated contexts: E4B's KV takes 28,672 bytes per position, so 32,000 positions (what any `maxNumTokens` of 32,003 or more, including 32,768, actually allocates) hold 917,504,000 bytes and 32,768 positions would hold 939,524,096; both figures are decimal MB. Claims LM-EXE-003, LM-EXE-006.
- **C13 (assigned to A2; data).** The decode logits buffer is FP16 whenever the GPU runs FP16 activations and the sampler *backend setting* resolves to GPU (the default on GPU), even when no GPU sampler loads and the CPU sampler reads the logits; AUDIT's "FP16 logits only with ... the GPU sampler" is right only if read as the setting. Claim LM-EXE-020.
- **NEW: AUDIT §2.3 decode-step description.** AUDIT (v0.18.0 line numbers) says each decode step refills the mask from a full copy of the token history and allocates a new ids buffer; that is still what ships (v0.18.0) but agello-next removed both (ours: `e43f9a8d`). Resolution: the AUDIT text describes the shipped build only. Claims LM-EXE-013, LM-EXE-035.
- **NEW: passive GPU wait vs Agello's benchmark flag.** Our commit `645aaf65` ("Metal waits sleep instead of spinning outside benchmark mode") doesn't take effect in Agello's engines as configured, because Agello sets `ExperimentalFlags.enableBenchmark = true`, which sets `is_benchmark` and requests the active wait. Resolution: the commit is correct for engines without benchmark parameters; Agello's configuration (in both builds) spins. Claim LM-EXE-038.

## Notes for other pages

- **engine-and-sessions.md (lm-engine):** an unset `maxNumTokens` becomes the metadata value or `((hint tokens + 1023)/4096 + 1) * 4096` in `MaybeUpdateAndValidate` before the environment exists (4,096 for E4B with no hint) (LM-EXE-005); `is_benchmark` is derived from benchmark params in `MaybeUpdateAndValidate` (LM-EXE-038); `MaybeUpdateAndValidate` also sets `disable_delegate_clustering = true` for Gemma 4 (`runtime/engine/engine_settings.cc` around line 508, not claimed here); the engine validates backend constraints of the main, vision-encoder and audio-encoder sections only (LM-EXE-028, LM-EXE-031); executors are called synchronously from `Tasks` (LM-EXE-041); KV snapshots use our raw Metal path (LM-EXE-018); no KV eviction in the executor (LM-EXE-066).
- **components.md (lm-components):** CPU sampler receives FP16 logits by default on the GPU (LM-EXE-020, relevant to C13 and our P6 FP16 greedy path); embedding lookups are CPU `CompiledModel` runs, default embedding = token 0's row (LM-EXE-015, LM-EXE-059); MTP samplers are greedy TOP_P k=1 (LM-EXE-024).
- **memory.md / models/gemma4-e4b.md (B1):** KV 28,672 B/position; 32,000-position cap; 4,096 default (LM-EXE-003, -005, -006); KV buffers are single-bank (`kGpuOptimizedInplace`) for Gemma 4, so no 2x ping-pong memory (LM-EXE-017); a `prefill_1024` BOOL mask is 1,024 x allocated-context bytes and is filled on the CPU for E4B (LM-EXE-009).
- **models/gemma4-e4b.md:** E4B and E2B files have no ExecutorMetadata, so image tokens get causal masks in LiteRT-LM (LM-EXE-008); MTP drafts 3 (LM-EXE-022); vision shrink factor 9 and audio 4 (LM-EXE-027, LM-EXE-030).
- **patches.md (B4):** `645aaf65` is bypassed by Agello's benchmark flag (LM-EXE-038); `e43f9a8d` (LM-EXE-013); `aec81cb7`, `585203d3` (LM-EXE-018).
- **apple-platform.md (B3):** prefill is synchronous on Metal (LM-EXE-012); NPU executor compiled out on iOS (LM-EXE-001), absent on macOS (LM-EXE-087); Agello runs vision and audio encoders on the CPU (LM-EXE-029).
- **troubleshooting.md:** "Audio backend constraint mismatch" for non-CPU audio (LM-EXE-031); "Prefill input length exceeds available state entries" when a prompt doesn't fit; `maxNumTokens` >= 32,003 silently becomes 32,000.
- **Agello (not a reference page; for the user):** with MTP on, temperature/top-k/top-p affect only the first token of each decode call (LM-EXE-024); `ExperimentalFlags.enableBenchmark = true` makes the GPU wait spin in both builds (LM-EXE-038).
