## Terms (for glossary.md)

| term | meaning | prefer / avoid |
| --- | --- | --- |
| `.litertlm` | LiteRT-LM's model container: 32-byte preamble, FlatBuffers header, 16 KiB-aligned typed sections | prefer "container"; avoid "bundle" (that is `.task`) |
| section | one typed byte range of a `.litertlm` file (`SectionObject`) | |
| `model_type` | the string item naming a TFLite section's role (`tf_lite_prefill_decode`, ...) | use the exact string |
| `BufferKey` | loader key: data type + lowercase `model_type` (or `name` for generic data) | |
| section hint | the `backend_constraint` and `prefer_activation_type` items of a section | avoid "selector": they never select among sections |
| header end offset | absolute byte offset where the header flatbuffer ends (uint64 at byte 24) | prefer over "header size" |
| GPU artisan (`GPU_ARTISAN`) | Google's closed GPU executor for `tf_lite_artisan_text_decoder` sections (`-gpu` files) | |
| TopK Metal sampler | Google's closed GPU sampler, `libLiteRtTopKMetalSampler` / `LiteRtTopKMetalSampler_*` | avoid "the GPU sampler" without naming the build |
| `TopPSampler` | the open CPU sampler (top-k, top-p, weighted draw; k 1 = argmax) | |
| greedy half path | Agello's `GreedyHalf` argmax over FP16 logits compared as integers (`fdd5bac7`) | |
| configured sampler backend | what `GetSamplerBackend` returns (GPU on a GPU engine), as opposed to the sampler that actually loads | |
| logit mask | `BitmapLogitMask` (hard), `SparseLogitMask` (soft), `CompositeLogitMask` | |
| mask runner | `LiteRtLogitMaskRunner`: applies masks in place on host memory or with a LiteRT graph on the accelerator | |
| constrained decoder | `ConstrainedDecoder`: per-row constraint states plus a mask runner | |
| thinking budget | `ThinkingBudgetConstraint`: forces the channel's end tokens after N thinking tokens | |
| end-of-media embedding | constant embedding from `tf_lite_end_of_vision` / `tf_lite_end_of_audio`, keyed by token −3 / −4 | |
| external weights | constant data outside the TFLite flatbuffer: after the graph (`Buffer.offset`) or in a `TFLiteWeights` section | |

## Contradictions

- **C10** (CPU sampling cost, 0.50 ms in TELEMETRY vs 0.044 ms in T7): both are means of the same `sample` telemetry span, a greedy CPU `TopPSampler` call including the logits read, on an M6 at level 2 with MTP off; 0.50 ms (`results/mac/2026-10-14/bench/tele-t2k.jsonl`) is a build before direct logits reads, 0.044 ms (`results/mac/2026-10-15/bench/t6-plain.jsonl`, the same binary as `p6-p6post`) after T5's direct reads and P6's integer argmax; neither measures top-k/top-p with k > 1. Claims LM-CMP-039, LM-CMP-040, LM-CMP-041.
- **C13** (FP16 logits): AUDIT's v0.18.0 rule is right about the condition, FP16 precision and the *configured* sampler backend GPU, which is the default on a GPU engine; but when the GPU sampler doesn't load (our build), the CPU `TopPSampler` receives those FP16 logits: v0.18.0's converts them to float, agello-next's (`fdd5bac7`) picks greedy directly over the halves; the 524,288-byte direct read per step confirms FP16 logits. Claims LM-CMP-028, LM-CMP-029, LM-CMP-030, LM-CMP-031.
- **NEW** (AUDIT §2.4, "The Metal TopK sampler is used only when the environment carries a Metal device"): correct, and additionally only when no WebGPU device option is set; the closed library is tried by `dlopen` and then through static function pointers. Claims LM-CMP-019, LM-CMP-020.

- **models/gemma4-e4b.md:** our file and Google's differ only in the sizes of sections 10 and 11 (LM-FMT-040); the main section keeps 2,197.9 MB of weights after the graph (LM-FMT-030); start and stop token IDs (LM-CMP-016); embedder and end-of-media signatures (LM-CMP-081).
