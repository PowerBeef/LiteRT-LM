## Terms (for glossary.md)

| term | meaning | prefer / avoid |
| --- | --- | --- |
| GPU Neural Accelerators | The matrix units of Apple10 GPUs (A19, M5, M6) that ML Drift reaches through Metal Performance Primitives tensor operations in `ConvAppleMPP` | Prefer "GPU Neural Accelerators"; avoid "Neural Engine" or "ANE" (not used by this stack) |
| `ConvAppleMPP` | ML Drift's convolution built on `mpp::tensor_ops::matmul2d`; Apple10 and MSL 4.0 only | Name the class; "the Neural Accelerator convolution" in prose |
| `ConvWaveMatrix` | ML Drift's convolution on cooperative 8x8 matrices (`simdgroup_matrix` on Metal); Apple7 to Apple9 in practice | "simdgroup-matrix convolution"; avoid "tensor cores" |
| `ConvGeneric` | ML Drift's portable tiled convolution; the fallback | |
| `FullyConnected` (`fc1x1_*`) | ML Drift's fully connected kernel for up to 16 rows (Apple, FP16), dequantizing INT2/INT4/INT8 weights in its loop | "fully connected kernel" |
| External weights | Weights that arrive as a runtime tensor (from the file or the KV cache) rather than baked into the kernel | |
| I4O4 / O4I4 | ML Drift weight layouts grouping 4 inputs x 4 outputs, inputs or outputs innermost; the V cache is I4O4, the K cache O4I4 | |
| Slice | 4 consecutive channels, ML Drift's unit of vectorized work | |
| Runtime check | `ConvRuntimeCheckDesc` / `SoftmaxRuntimeCheckDesc`: bounds read from `param_tensor` at run time (end of the filled part, our window start) | |
| `param_tensor` | INT32 `[1, 1, 1, 7]` graph input: first position, end, end, then zeros | |
| Bounded attention | Our LiteRT rewrite of the select and softmax between the two attention products into a fused mask, a bounded reduction and an in-kernel softmax | Mark "(ours)" on first use |
| Window start | `max(0, p0 - W + 1)` rounded down to 32 keys (`RuntimeWindowStartSlice`), where local-layer kernels start reading keys | |
| Offset storage (quantized values) | INT2/INT4/INT8 values stored unsigned with +2/+8/+128 and dequantized as `(u - shift - zero_point) x scale` | Avoid calling the KV cache "uint8 data": it is INT8 stored with an offset |
| INT8 path (Apple10 prefill) | Weights converted to INT8, activations quantized per token to INT8, INT32 accumulation, FP32 dequantization | Avoid bare "W8A8": say the activation quantization is per token and dynamic |
| Conversion cost | ML Drift's estimate of a separate weight conversion relative to the convolution; above 20 the convolution reads the original weights | |
| `CalculationsPrecision` (`kF16`, `kF32F16`, `kF32`) | ML Drift's precision modes: FP16 storage and accumulation / FP16 storage with FP32 accumulation / FP32 | |
| ML Drift family | ML Drift's own Apple GPU family enum, derived from the GPU name (Apple7 to Apple10 here) | Don't equate it with Metal's family numbering without checking (see notes) |

## Contradictions

- **C12** (window-aware kernels): at ML Drift `15fa9e2` the window-aware kernels are `FullyConnected`, `Softmax`, `Softmax1x1`, `ConvAppleMPP` (only when it tiles K itself) and `ConvWaveMatrix`; `ConvGeneric`, `BatchedMatMul`, the weights converter and the elementwise kernels are not. Track T4's list predates `15fa9e2`; VALIDATION's addition of `ConvWaveMatrix` is right. Claims: MD-KRN-061, MD-KRN-056, MD-KRN-057, MD-KRN-058, MD-KRN-060.
- **NEW-1** (track T4 step 2: the Apple matrix-unit convolution "does the same per K tile"): on Apple10, E4B's prefill query-key products run `ConvAppleMPP` without manual K tiling (FP16-converted K, DHWBCC4 buffer source, no source bound), so the window is off for them; only the value products and the reduction use it there. Claims: MD-KRN-059, MD-KRN-058, MD-KRN-024.
- **NEW-2** (track T4 "Next": INT8 K/V converted to FP16 for prefill "over the whole capacity"): the weights converter returns early past the filled length (`dst_end_ch_index` / `src_end_ch_index`), so the conversion is bounded to the filled part, rounded up; what it doesn't skip is the keys below the window. Claim: MD-KRN-063.
- **NEW-3** (Run A brief: "RoPE (FP32 angles from INT32 positions)"): E4B's rotary angles are FLOAT32 in the file but FP16 on the GPU at LiteRT-LM's default precision (`kF16` makes every internal FLOAT32 tensor FP16, and SIN/COS/MUL/CAST run in the tensor type). ML Drift's dedicated RoPE kernels do compute FP32 angles, but E4B doesn't use them. Claims: MD-KRN-075, MD-KRN-076, MD-KRN-073, MD-KRN-074, MD-KRN-007.

Our pass runs from `ApplyCustomTransformations` (the GraphFloat32 path); `use_ir_model` defaults to false in `delegate_options.h`.
- **ml-drift/architecture.md (md-architecture):** family mapping by GPU name (MD-KRN-079) and the simulation switch (MD-KRN-080); `GetTensorDescForValue` makes FLOAT32 values FP16 at `kF16`/`kF32F16` (MD-KRN-007); the Metal environment registers 8x8x8 wave-matrix ops only for MSL 2.3+ and family Apple7+ (MD-KRN-040); `SupportsConvAppleMPP` needs MSL 4.0 (MD-KRN-016).
- **ml-drift/metal-backend.md (md-architecture):** `EncodeWithCommandBuffer` encodes every node per run except disabled optional tags, so per-run weight conversions are real per-run work (MD-KRN-089); wave-matrix lowering to `simdgroup_matrix` / `simdgroup_multiply_accumulate` (MD-KRN-041); `ConvAppleMPP`'s generated MSL includes MetalPerformancePrimitives (MD-KRN-034).
- **apple-platform.md:** the family split for E4B (MD-KRN-081, MD-KRN-002, MD-KRN-003); Apple10 prefill quantizes activations to INT8, Apple7 to Apple9 stay FP16 (MD-KRN-081); digit fidelity 70/70 on both paths (MD-KRN-090). Also: agello-bench's machine record for the M6 says `gpuAppleFamily: 11` while ML Drift calls it Apple10 (`docs/agello/results/mac/2026-10-15/bench/t4b-ab-t16k-kv32768.jsonl`), so the two numberings differ; worth a sentence there (no claim made here).
- **models/gemma4-e4b.md:** the single INT2 tensor (167.8 MB) is the output projection (MD-KRN-083); cache_update attributes and no ring buffer (MD-KRN-068); the rotary math as CAST/MUL/SIN/COS, FP16 on the GPU (MD-KRN-073, MD-KRN-075); decode attention destination `[1, 2, 4, T]`, verify 16 rows (MD-KRN-013); `sliding_window` 512 in the config (MD-KRN-052).
- **litert-lm/executors.md:** `param_tensor` holds start, end, end, then zeros (MD-KRN-049); FLOAT16 activations by default on the GPU (MD-KRN-008); the text embedder is compiled for the CPU off Android (MD-KRN-078).
- **memory.md:** prefill graphs hold converted weight copies: on Apple7 to Apple9 `prefill_1024` converts 163 INT4 and 47 INT8 tensors to FP16, on Apple10 both prefill graphs convert them to INT8, plus FP16 copies of the K/V caches (MD-KRN-002, MD-KRN-003, MD-KRN-019). How much memory those intermediate tensors take, and whether ML Drift's memory planner shares them across nodes, is not verified.
- **troubleshooting.md and #3913 texts:** the mechanism is FP16 tensors at `kF16`, not FP32 angles (MD-KRN-075); ML Drift's own RoPE kernel is FP32 (MD-KRN-076).
