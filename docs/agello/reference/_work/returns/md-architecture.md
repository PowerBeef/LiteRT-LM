## Terms (for glossary.md)

| Term | Meaning | Prefer / avoid |
| --- | --- | --- |
| ML Drift | Google's GPU inference engine behind LiteRT's GPU accelerator (successor of the TFLite GPU delegate) | Prefer "ML Drift"; avoid "the GPU delegate" for the engine itself |
| `GraphFloat32` | ML Drift's input graph (nodes with typed operations, values with BHWC tensor refs) | — |
| `GpuModel` | ML Drift's backend-neutral compiled graph: nodes (`GpuNode` + `GPUOperation`) and tensor descriptors | — |
| `GPUOperation` | One generated GPU kernel with its arguments and work-group size | Avoid "op" when the TFLite operation is meant |
| Apple family (ML Drift) | ML Drift's `AppleInfo::Family` (Apple1–Apple10), derived from the device name | Say "ML Drift family Apple10"; avoid presenting it as `MTLGPUFamily` |
| Calculation precision | `CalculationsPrecision` kF32 / kF16 / kF32F16 | Distinguish from a tensor's data type |
| Storage type | `TensorStorageType`: buffer, image buffer, 2D/3D/array texture, single-channel-group 2D texture | — |
| Fused node | A `GpuNode` whose kernel includes elementwise consumers (`a -> b -> c`) | — |
| Selector | Code that picks the `GPUOperation` for a graph node (`OpSelector`, `GPUOperationFromNode`) | — |
| Simulation switch | `AGELLO_SIMULATE_APPLE_GPU` (ours): another Apple GPU's kernel choices on this device | Avoid "emulation" |
| Flush period | Kernels per command buffer in `EncodeWithCommandQueue` (256 in LiteRT's Dispatch) | — |
| Program cache (Metal) | Serialized `GpuModel` + MSL source + work-group sizes; restore recompiles the source | Avoid "compiled shader cache" for Metal |
| Residency set | `MTLResidencySet` LiteRT's Metal backend fills with constants and external tensors | — |
| ICB | Indirect command buffer; present in ML Drift's Metal code but disabled | Spell out on first use |

## Contradictions

- **C12** (window-aware kernels) is md-kernels'; nothing in my pages states which kernels are window-aware beyond linking kernels.md.
- **NEW-A5-1: when graph dumps run.** `docs/agello/TELEMETRY.md`'s level table lists "graph dumps" under level 4 (deep), while its own "GPU graphs" row and the code say any level: `DumpGraphForTelemetry` depends only on `AGELLO_TELEMETRY_GRAPH_DIR`. Resolution: graph dumps are independent of the telemetry level. Claim MD-MTL-034 (conflicts_with recorded).
- **Not a contradiction, worth a note: "M6 reports Apple11" (AUDIT §8)** vs ML Drift's family Apple10 for the M6. They measure different things: AUDIT refers to Metal's `MTLGPUFamily` support (not verified here), ML Drift's enum stops at kApple10 and is derived from the name. Claims MD-ARC-003/004. Pages say "ML Drift family" throughout.
- AUDIT §8's other Metal statements (classic queues, re-encode every node, 256 kernels per command buffer, residency off by default, ICBs hard-disabled, runtime `newLibraryWithSource`) agree with the code at the pins (MD-MTL-020/022/023/007/029).

## Notes for other pages

- **litert/ml-drift-delegate.md:** `GpuBackendMetal` creates and fills the residency set on iOS 18+ even when the option is off; only queue attachment, `requestResidency` and the heartbeat depend on it; intermediates are never added (MD-MTL-027/028). A program-cache hit on Metal still recompiles every node's MSL (MD-MTL-024/025). `InitFromGpuModel(id<MTLDevice>)` builds a new `Environment` (and runs `xnn_initialize`) per context (MD-MTL-002). Shared `MemoryManager` across contexts (MD-MTL-013).
- **kernels.md:** MD-KRN-017 says LiteRT-LM leaves source-quantized FC/conv on unless the setting is false; `EngineSettings` also sets it false for models whose metadata has no well-known `llm_model_type` (generic models) when the app leaves it unset (MD-ARC-058).
- **apple-platform.md:** device → ML Drift family table and compute-unit table (MD-ARC-003/008); observed names `Apple A19 Pro GPU` (iPhone 17 Pro) and `Apple M6` (MD-ARC-006/007); unknown names fall to Apple1 (MD-ARC-004); MSL 4.0 detection via `MTLGPUFamily` 5002 (MD-MTL-003); simulation limits (MD-ARC-017).
- **memory.md:** ML Drift's intermediates are pooled per backend and never freed until the backend dies; offset-plan cap 128 MiB; all `MTLBuffer`s are shared storage (MD-MTL-012/013/015).
- **tools.md:** graph dumps, debug groups, per-kernel timing and `NsPerGpuTick` (MD-MTL-032/033/034/040); the simulation switch (MD-ARC-016/019).
- **build-and-release.md:** the ML Drift fork's Metal target depends on `@agello_telemetry`, so it only builds where that repository is declared (MD-MTL-031).
- **stack.md:** threads: all ML Drift work (build, compile, encode) runs synchronously on the caller's thread; compilation is serial.
- **patches.md:** ML Drift commits `5aaea039f9`, `04fe7b712c`, `55196d78cf` (telemetry), `ef08a67858` (simulation), LiteRT `362759838` (simulation cache keys).

- The ML Drift revision inside Google's prebuilt v0.18.0 binary, and whether its family table matches `1b18771`.
- How much the OS shader cache shortens `newLibraryWithSource` across launches; how load time splits between graph building and MSL compilation (no telemetry span around `CompileOperations`).
- Device names reported by A19 (non-Pro), A18 and M5 GPUs are taken from ML Drift's table, not observed.
- Argument-buffer mode: scalar changes after `UpdateParams` aren't re-encoded (not on our path, not tested).
- Effect of residency sets on Agello's latency or memory pressure: not measured.
