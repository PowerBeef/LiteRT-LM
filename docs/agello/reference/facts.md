# Facts register

> **Scope:** the canonical register of numbers and user-facing facts about LiteRT-LM, LiteRT, ML Drift
> and the models Agello uses: one row per fact, with its value, what kind of fact it is, the
> conditions it holds under, the verified claims behind it, the older figures it replaces, where it is
> used, and a sentence safe to quote. User docs, commit messages and upstream reports quote from
> here. **Out of scope:** how things work (each row links the page that owns the topic); test counts
> (Agello facts, see [F-130](#f-130)); terms ([glossary.md](glossary.md)).
> **Pinned to:** LiteRT-LM `7b872544`, LiteRT `362759838`, ML Drift `15fa9e2`; what Agello ships:
> LiteRT-LM `85b1a776` with Google's prebuilt v0.18.0 `CLiteRTLM.xcframework`; Agello `93122b6`;
> models per `tools/agello-docs/pins.json`.
> **Applies to:** Apple (iOS, macOS) unless a row says all platforms. **Last verified:** 2026-10-15

## Summary

- Every row has a stable fact ID (`F-001` …). Quote a fact by its ID in commit messages and issue
  drafts ("F-041"), and copy its safe wording rather than paraphrasing the value.
- The **Source** column names the verified ledger claims (verdict verified or corrected) that back
  the row; the hidden tags after them let `check_refs.py` confirm each one is still verified. Rows
  derived here from verified inputs cite a claim of this page (`X-FCT-…`) with its formula.
- Keep apart what the **model** was trained for, what the **file** exports, what the **runtime**
  allocates, and what **we measured**: the same word ("context", "KV size", "vision tokens") has a
  different value in each, and most contradictions in older notes come from mixing them.
- Performance figures are only from results files in `docs/agello/results/` (ours, with build and
  device) or attributed to Google with a date. A figure without its build is not quotable.
- Superseded values are kept in each row so a reader who finds an old figure can tell why it
  differs; the dossier of corrections to existing docs is `_work/contradictions.md`.

## Concepts

| Class | Meaning | Precedence when sources disagree |
| --- | --- | --- |
| model as trained | A property of the Gemma 4 or EmbeddingGemma checkpoint: official `config.json` at a pinned Hugging Face revision, the model card, the technical report | the official config, then the card |
| file as exported | A property of a `.litertlm` file's bytes (sections, signatures, tensor shapes, hashes) | the file |
| runtime behavior | What LiteRT-LM, LiteRT or ML Drift does at the pins (or Agello's code at `93122b6`, marked "Agello") | code at the pin |
| measured by us | A record in `docs/agello/results/` or `generated/`, with build, device and settings | the record and its conditions |
| vendor claim | Google's or Apple's published figure or statement, attributed and dated | quote as theirs, never as ours |
| project record | Pins, versions, counts of commits or drafts, upstream status on a date | git and GitHub at the date |

Builds named in rows: **shipped** = the wrapper `85b1a776` with Google's prebuilt v0.18.0 binary
(what Agello users run); **documented** = our build at LiteRT-LM `7b872544` + LiteRT `362759838` +
ML Drift `15fa9e2`; a **build id** (12 hex digits, [F-012](#f-012)) names one compiled framework.

## Limits and failure modes

- **Dates.** Every value is as of its date column. Hugging Face revisions, GitHub state (issue
  comments, pull-request counts, branches) and vendor cards move; re-read before quoting a row whose
  class is vendor claim or project record.
- **Builds.** Measured rows name a build id or commit. Most measurements predate the documented pin
  (`2e54fbdb9ca9`, `fc71d704a349`, `b2d0db54134f`, …); a row says so when it matters. Build
  `2e54fbdb9ca9` is four commits before `7b872544` and runs the same Apple10 GPU path (F-108).
- **Rounding.** MB and GB are decimal (10⁶, 10⁹ bytes) unless a row says MiB or GiB; Agello prints
  the app limit with one decimal of bytes / 10⁹, so 8 GiB shows as "8.6 GB".
- **Agello rows** (class "runtime behavior (Agello)") are Agello's code at `93122b6`; they change
  with the app, not with the runtime pins.
- **Not here:** test counts (F-130 states the rule), and numbers that live only in drafts or notes
  without a raw record (F-081, F-116 record two such cases).
